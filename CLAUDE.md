# Проект

Telegram-бот. На любое сообщение (текст, команда, стикер, фото и т. д.) отвечает саркастично и никогда не отвечает прямо на заданный вопрос. Ответы генерирует Gemini. Общение с автором проекта — по-русски.

Личные заметки лежат в `CLAUDE.local.md` (в git не попадает).

## Стек и файлы

- `bot.py` — весь бот. Python 3.9, только стандартная библиотека (без pip-зависимостей).
- `.env` — `BOT_TOKEN` (токен Telegram-бота) и `GEMINI_API_KEY` (права 600). Исключён из git через `.gitignore` (`.env`, `.env.*`, кроме `.env.example`). Секреты не выводить в чат, логи и коммиты, не добавлять в код.
- `.env.example` — шаблон без значений.
- Репозиторий публичный: личные данные автора (имя, почту, локальные пути) в файлы не добавлять.

## Как работает бот

- Получение обновлений: long polling (`getUpdates`, `allowed_updates=["message"]`). Вебхук не используется, при старте снимается.
- При старте вызывается `deleteWebhook(drop_pending_updates=True)`, а сообщения с датой раньше запуска пропускаются: всё, что пришло, пока бот был офлайн, игнорируется.
- Ответ: `gemini_reply()` отправляет текст сообщения (или подпись к медиа) в Gemini API (`generateContent`, ключ в заголовке `x-goog-api-key`). Системная инструкция `SYSTEM_PROMPT`: сарказм, не отвечать прямо на вопрос, 1–3 предложения, без мата и оскорблений по национальности или религии.
- Два режима в `SYSTEM_PROMPT`: сарказм (по умолчанию) и милый. Милый режим включается, когда собеседник злится, обижается, ругается или прощается; бот тогда ласковый, извиняется, предлагает остаться (игра, интересный факт, вопрос о собеседнике) и может отвечать прямо. Без манипуляций: без давления на вину и жалость, без угроз, без «мне будет грустно без тебя». Когда собеседник успокоился, бот возвращается к сарказму. Решение о режиме принимает модель по контексту (отдельного классификатора нет).
- Исключение: если человек пишет о настоящей беде (горе, страх, мысли о самоповреждении), сарказма нет, бот отвечает серьёзно и по-доброму, советует обратиться к близким или в местную экстренную службу, без конкретных номеров телефонов.
- Память чата: последние 10 реплик на `chat_id` (`_history`, только в оперативной памяти, при перезапуске пропадает). Нужна, чтобы бот помнил, что собеседник уже злился. Заготовка при сбое Gemini в историю не попадает.
- Модели перебираются по порядку при сбоях (503, 404 и др.): `gemini-3.5-flash-lite`, `gemini-3.8-flash`, `gemini-3.1-flash-lite`. Переопределить можно в `.env`: `GEMINI_MODEL=model-a,model-b`. Если все модели недоступны, бот отвечает заготовленной язвительной отговоркой.
- Ответ модели уходит без `parse_mode` (обычный текст), перед ним показывается статус «печатает».
- Сообщение без текста (стикер, фото без подписи) передаётся модели как «пользователь прислал сообщение без текста».
- Сообщения обрабатываются по одному; ответ Gemini занимает около 10 секунд.
- Логируется каждое входящее сообщение (chat_id).
- `get_weather_text()` (Open-Meteo, Астана) и `get_btc_text()` (CoinGecko) остались в `bot.py` от прошлой версии, но в ответах не используются.

## Запуск

```bash
python3 bot.py
```

Остановка — `Ctrl-C`.

## Подводные камни

- Одновременно должен работать только один экземпляр бота. Иначе Telegram отвечает `409 Conflict: terminated by other getUpdates request`. Перед запуском проверять процессы `bot.py` (`ps -eo pid,tty,command | grep "[P]ython bot.py"`). Закрытие вкладки терминала не всегда убивает процесс.
- В `Telegram.call` таймаут соединения называется `http_timeout`, потому что `timeout` — параметр самого `getUpdates` (long polling). Раньше их имена совпадали и бот падал с `TypeError`.
- Старые модели Gemini (`gemini-2.5-*`) для новых ключей уже недоступны (404). Новые модели часто отвечают 503 из-за нагрузки, поэтому нужен список запасных.
- Бот работает, пока открыт процесс: фонового запуска или деплоя пока нет.
